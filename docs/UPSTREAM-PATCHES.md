# Patches to BentoPDF code

Paperwing keeps BentoPDF's code unmodified wherever possible, so new BentoPDF releases merge in
cleanly. The exceptions are listed here. When merging a BentoPDF release, check whether upstream
has fixed each one; if it has, take upstream's version and remove the entry.

| File                                     | Change                                                                                                                                                                                                                                                                   | Why                                                                                                                                                                                                                                                                                                       |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `vite.config.ts`                         | Two lines registering `reskin/vite-plugin-reskin.ts`                                                                                                                                                                                                                     | Injects Paperwing's integration layer at build time                                                                                                                                                                                                                                                       |
| `src/js/editcore/streamsplice.js`        | The `TJ` array pattern in `showOperators` no longer lets a backslash match two ways                                                                                                                                                                                      | Catastrophic regex backtracking (ReDoS) on crafted PDF content streams (CodeQL `js/redos`)                                                                                                                                                                                                                |
| `src/js/editcore/type3surgery.js`        | The array branch of `TOKEN_RE` no longer lets `(` and `<` match both as string/hex starts and as plain characters                                                                                                                                                        | Same ReDoS class (CodeQL `js/redos`)                                                                                                                                                                                                                                                                      |

## Paperwing's name in BentoPDF's tools

BentoPDF's pages, code and interface strings show its name in places (page titles, messages,
the Markdown editor's sample, the files some tools save). `reskin/brand.mjs` puts Paperwing's
name there while building: `reskin/vite-plugin-reskin.ts` for the pages and `src/js` code,
`desktop/scripts/build-web.mjs` for `dist/locales` (keys too: `ui.json` is keyed by the English text, which the code looks up rebranded). BentoPDF's files aren't changed.

Kept as they are: BentoPDF's copyright notices (any line with "©" or "All rights reserved"), web
addresses and storage keys (lowercase, so existing settings carry over), and the credits (README,
NOTICE.md, the About box). `desktop/bench/check-branding.mjs` fails if the build shows BentoPDF's
name anywhere else; `check-tools.mjs` checks what every tool shows in the running app, including
BentoPDF's website content (self-hosting, sponsors, Discord). When a BentoPDF release adds a
file its tools save under its name, add it to `FILE_NAMES` in `brand.mjs`.

## The desktop app's words in BentoPDF's tools

BentoPDF's tools are written for a website: "Upload certificate", "Save & Download Signed PDF",
"Runs entirely in your browser". In the desktop app nothing is uploaded or downloaded, so that
wording made people think their files went to a server. For the desktop build only
(`PAPERWING_DESKTOP=1`, set by `desktop/scripts/build-web.mjs`), `reskin/desktop-words.mjs`
rewords them while building, in the same places as the name: the English interface strings
(values only; the English `ui.json` is never loaded), the tool pages' text and tooltips (not
their markup or scripts), and the text in `src/js`'s string literals (found with TypeScript's
parser, so module names, selectors, translation keys, object keys and anything compared against
are left alone). Upload becomes Choose, Download becomes Save, "downloaded" becomes "created"
(a PDF result opens in a new tab, not yet on disk), and "in your browser" / "your device"
become "on your computer". Paperwing's own tooltips (`src/reskin/labels.ts`) do the same through
`__PAPERWING_DESKTOP__`. The browser build keeps BentoPDF's wording.

Kept as they are, because they're true in the desktop app too: "never uploaded", "no uploads",
questions like "Is my PDF uploaded?", other tools that "upload your files to a server", and the
real downloads (the conversion engines and fonts on first use). `check-tools.mjs` lists what
every tool still shows with upload, download, browser or device in it (`serverWords` in its
report). When a BentoPDF release adds wording that comes out wrong, add a rule or a kept phrase
to `desktop-words.mjs` and a case to `src/tests/paperwing-desktop-words.test.ts`.

## Patches to the viewer package

The EmbedPDF viewer (`bentopdf-viewer`, a BentoPDF dependency) is patched while
building, by `reskin/vite-plugin-reskin.ts`; the package itself isn't changed.
Each patch checks that the code it replaces is there exactly as expected and is
skipped with a warning otherwise (for example after a viewer update).
`PAPERWING_VIEWER_PATCHES=0` builds without them.

| Patch          | Why                                                                                                                                                                                     |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| State snapshot | The viewer's store copied its whole state on every read, once per listener on every change: half of the main thread while scrolling. One snapshot per change now                        |
| Wheel zoom     | Ctrl+mouse wheel zoomed out to the minimum in one notch (and doubled per notch in). About 15% per notch now, eased; trackpad pinches unchanged                                          |
| Tab spaces     | PDFs whose space character is a tab (wkhtmltopdf's): copied text was full of tabs and phrase searches found nothing. Tabs read as spaces; phrase searches on such pages also match tabs |
| Font faces     | Fonts a PDF doesn't embed were all drawn in one sans-serif face. Latin text now gets a fallback chosen by name with matching widths (Liberation Serif/Sans/Mono, Carlito, Caladea)      |

`zgapdfsigner` (timestamps, digital signatures) is patched the same way:

| Patch                | Why                                                                                                                                             |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| Signer browser check | Its browser detection is never true inside a bundled module, so it didn't use `fetch` and refused the desktop app's relay for timestamp servers |
